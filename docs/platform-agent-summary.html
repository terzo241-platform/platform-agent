What Is This?

An AI agent that lets developers interact with CI/CD pipelines, source control, GitOps deployments, and infrastructure using natural language. Instead of learning 4 different tools (GitHub, Tekton, ArgoCD, Terraform), developers talk to one agent.


Example: "Deploy my-api to staging" → The agent figures out which CI/CD system runs it, triggers the pipeline, monitors status, and reports back. No manual clicking through UIs.

Step by step:
  1. Developer asks in natural language via any MCP-compatible client
  2. MCP Server receives the request, routes to the right tool (17 available)
  3. ADK Agent reasons about intent, selects tools, applies guardrails
  4. Provider Registry auto-detects which backend to call (GitHub? Tekton? ArgoCD?)
  5. Action executes against the real infrastructure, with audit logging
  6. Result returns to the developer in plain language

Key Design Decisions (Internet-Grounded)

Why Google ADK?

21.6k GitHub stars, Apache-2.0, GCP-native. Ford has a 6-year Google partnership ("Team Upshift"). ADK supports multi-LLM (Gemini + Claude + OpenAI), MCP-native tool exposure, and deploys to Cloud Run / GKE / Vertex AI Agent Runtime.

Why Not RAG?

Ford has zero public engineering docs — corpus is small enough to fit in context. Knowledge-as-Code: version-controlled YAML/MD in knowledge/ directory, loaded as agent instruction at startup. Contributable by any team member.

Why Provider Abstraction?

No single point of failure. Ford uses both GitHub Actions and Tekton. Protocol-based providers (CIProvider, SCMProvider, GitOpsProvider) let the agent auto-route to the right backend per repo. Swap providers without changing tools.

Why MCP over Custom API?

MCP spec 2026-07-28 is the industry standard — 10,000+ servers in production. One server works with Claude Code, VS Code Copilot, Cursor, Gemini CLI, and any future client. Tool annotations (readOnly/destructive/idempotent) enable automatic safety UX.

Enterprise Guardrails (OWASP LLM06)

4-Layer Protection

  1. Tool Scoping — Each tool declares its blast radius
  2. Pre-execution — Rate limiting + RBAC checks
  3. Human-in-the-Loop — Prod actions require confirmation
  4. Audit Trail — Every action logged (BigQuery in prod)

Environment Rules

devAuto-approve all
stagingAuto-approve + warn
prodAlways require human approval

Separation of duties: PR author ≠ merger (enforced in code)
