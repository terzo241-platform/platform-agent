The Problem We All Know

What enterprise platform teams struggle with — universally

Fragmented CI/CD

  • Every team builds their own pipeline from scratch
  • Security scanning is optional, inconsistent, or absent
  • No supply chain enforcement (SBOM, signing, provenance)
  • Onboarding a new team takes weeks, not minutes

Manual Infrastructure

  • Infrastructure provisioning requires tickets + waiting
  • No golden paths — every team reinvents the wheel
  • Drift between environments (dev works, prod doesn't)
  • No guardrails — one misconfiguration = incident

Invisible Engineering

  • No DORA metrics — can't measure what you can't see
  • No data for leadership conversations about velocity
  • AI code generation inflating throughput without quality tracking
  • ROI of platform investments is faith-based, not data-driven

Tribal Knowledge

  • Platform practices live in people's heads, not in code
  • One person leaves = knowledge disappears
  • Teams ask the same questions in Slack every week
  • No self-service — everything requires a platform engineer

Unified CI/CD

Teams get enterprise-grade CI by adding 6 lines of YAML

Reusable Workflows

  • Python CI (ruff + pytest + Bandit)
  • Node CI (lint + test + Playwright sharding)
  • Java CI (Maven/Gradle + SpotBugs + OWASP)
  • Security scan (Trivy + gitleaks + CodeQL v4)
  • Container build (Docker + Trivy + cosign + SLSA)
  • Deploy to Cloud Run (OIDC, zero stored credentials)

What Teams Get for Free

  • Vulnerability scanning on every PR
  • Supply chain security (SBOM + provenance + signing)
  • Secret detection (gitleaks) before code ships
  • Container scanning before image push
  • OIDC auth (no secrets in GitHub, ever)
  • 3-env deploy: dev (auto) / staging (tag) / prod (approve)
"The golden path is the only path. Teams don't opt in to security — they'd have to opt out."
2

Infrastructure as Code

Production-grade infra with 7 lines of config. Every validation maps to a past lesson learned.

Golden Path Modules

  • Cloud Run service (13 validations, enforced labels)
  • GCS bucket (public access blocked, versioning, lifecycle)
  • Environment defaults: dev (scale 0-3) / staging (1-5) / prod (2-20)
  • Same module whether caller is human, CI, or AI agent

GitOps Workflow

  • PR opens: terraform plan runs, output posted as PR comment
  • PR merges: terraform apply runs automatically
  • Promotion workflow: dev → staging → prod with skip prevention
  • Concurrency lock: only one apply per environment at a time
"Every validation in the module maps to a past incident. The module is organizational memory."
3

AI Agent Platform

Developer says "deploy my app to staging" — agent handles the rest

Architecture Decisions

  • Google ADK (GCP-native, Ford-Google partnership)
  • Provider abstraction: GHA / Tekton / ArgoCD — agent doesn't care
  • MCP server for IDE integration (Claude Code, VS Code, Cursor)
  • Knowledge-as-Code over RAG (tribal knowledge in YAML, not vectors)
  • 4-layer guardrails (OWASP LLM06 mitigation)

What Developers Can Do

  • Slack: "@agent deploy sample-app to staging"
  • Slack: "@agent create a new Python service called data-pipeline"
  • IDE: use MCP tools directly in VS Code / Claude Code
  • CLI: ford-agent run "show me DORA metrics for my team"
  • All paths enforce separation of duties + prod approval gates

Why a 5th Metric?

  • AI code generation inflates deployment frequency
  • More PRs merged doesn't mean more value delivered
  • Rework rate tracks: are we shipping quality or churn?
  • No enterprise tool measures this well yet — we're ahead

What I Don't Know Yet

This is my starting hypothesis — not my final answer. I need to learn Ford's reality first.

Current CI/CD Landscape

What are teams using today? Tekton, Jenkins, custom scripts? What works, what doesn't? What customizations do teams depend on?

Team Constraints

Compliance requirements, air-gap restrictions, data residency, approval workflows. What can't change vs. what teams want to change?

Organizational Dynamics

Which teams are eager to adopt? Which are resistant? Who are the internal champions? What's been tried before and failed?

Existing Tooling + Knowledge

What tribal knowledge exists? What documentation is missing? Are there existing platform initiatives I should align with?

"The worst thing an architect can do is arrive with all the answers before understanding the questions."

Everything I've built is a prototype to accelerate discovery — not a prescription to impose.

Proposed 90-Day Roadmap

Phased approach — discover first, then validate, then expand

Phase 1: Discover

Week 1-4

  • Map current CI/CD + infra landscape
  • Interview 5-8 teams (pain points)

  • Understand compliance constraints
  • Assess GHEC EMU capabilities

Phase 2: Pilot

Week 5-8

  • Adapt POC to Ford's constraints
  • Deploy with one pilot team
  • Measure before/after DORA metrics
  • Collect feedback, iterate
  • Document what works at Ford scale

Phase 3: Validate

Week 9-10

  • Expand to 3-5 teams
  • Measure adoption friction
  • Refine golden paths
  • Build internal champions

Phase 4: Propose

Week 11-12

  • Present data-driven results
  • Org-wide rollout proposal
  • Vendor evaluation (Faros AI / DevLake)
  • Scaling architecture for 80+ teams

This timeline adapts to what I discover. Phase 1 output determines everything after it.
